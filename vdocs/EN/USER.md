# T4n OS Repository - User Guide

Welcome to the **T4n OS Repository**. This repository provides officially compiled, signed, and maintained binary packages (`.xbps`) for T4n OS and Void Linux systems.

 **Web Package Search Engine:** Browse, filter, and find all available packages easily at **[repo.t4nlabs.web.id/site/glibc.html](https://repo.t4nlabs.web.id/site/glibc.html)**.


## Supported Architectures
Our repositories are built to support a wide range of hardware architectures:
- **x86_64** (Standard 64-bit PC)
- **i686** (32-bit PC)
- **aarch64** (64-bit ARM)
- **armv6l** & **armv7l** (32-bit ARM / Raspberry Pi)

## 1. Adding the Repository

You can add the repository using our automated installer (Recommended) or manually.

### Option A: Automated Installer (Recommended)
Simply run this one-line command in your terminal. It will automatically detect your architecture, add the repository, and import the public signing key:

```bash
curl -sL https://t4n-labs.github.io/repo-glibc/install.sh | sudo sh
```

### Option B: Manual Setup
**Step 1: Create the configuration directory (if it doesn't exist)**
```bash
sudo mkdir -p /etc/xbps.d
```

**Step 2: Add the repository configuration**
Choose the command that matches your system's architecture:

```bash
# For x86_64 (Standard 64-bit PC)
echo 'repository=https://t4n-labs.github.io/repo-glibc/x86_64' | sudo tee /etc/xbps.d/10-glibc.conf

# For i686 (32-bit PC)
echo 'repository=https://t4n-labs.github.io/repo-glibc/i686' | sudo tee /etc/xbps.d/10-glibc.conf

# For aarch64 (64-bit ARM)
echo 'repository=https://t4n-labs.github.io/repo-glibc/aarch64' | sudo tee /etc/xbps.d/10-glibc.conf
```
*(Note: We also maintain `repo-musl`, `repo-server`, and `repo-security`. Adjust the URL and `.conf` filename accordingly if you are using those.)*

**Step 3: Synchronize the package database**
Update your local package index to recognize the new repository:
```bash
sudo xbps-install -S
```

##  2. Searching and Installing Packages

### Searching for Packages
You can search for available packages in the T4n OS repository using the terminal:
```bash
xbps-query -Rs "package_name"
```
*Example: `xbps-query -Rs "zvc"`*

Alternatively, use our **Web Package Search Engine** (see section 3 below) for a graphical interface.

### Installing a Package
Once you have found the package you want, install it using:
```bash
sudo xbps-install package_name
```

## 3. Using the Web Package Search Engine

We provide a fast, lightweight web interface to browse and search all available packages at **[repo.t4nlabs.web.id/site/glibc.html](https://repo.t4nlabs.web.id/site/glibc.html)**.

**Key Features:**
- **Live Search:** Instantly filter packages as you type (with a 110ms debounce for smooth performance).
- **Architecture Tabs:** Filter packages by architecture (`x86_64`, `aarch64`, etc.) with live counters showing how many packages are available for each.
- **Pagination:** Clean `[1] [2] [3] ... [Last]` navigation for large result sets.
- **Shareable URLs:** The search state is saved in the URL hash (e.g., `#q=vim&arch=x86_64&page=2`), allowing you to bookmark or share specific searches.
- **Keyboard Shortcuts:** 
  - Press `/` to instantly focus the search bar.
  - Press `Esc` to clear the search query.
- **One-Click Copy:** Click the `xbps-install ⧉` button next to any package to copy the installation command directly to your clipboard.

## 4. Removing the Repository

If you no longer wish to use the T4n OS repository, simply remove the configuration file and resynchronize:

```bash
sudo rm /etc/xbps.d/10-glibc.conf
sudo xbps-install -S
```

## ❓ Troubleshooting & FAQ

**Q: I get an error: `repository is not signed, refusing to continue!`**
**A:** T4n OS repositories are cryptographically signed. If you used the automated installer (`curl ... | sudo sh`), the public key should already be imported. If you set it up manually, ensure your configuration file is correctly formatted. You can force a resync with `sudo xbps-install -S`. 

**Q: I can't find a specific package using `xbps-query`.**
**A:** Ensure you have run `sudo xbps-install -S` after adding the repository. If it still doesn't show up, the package might not be available for your specific architecture. Check our Web Search Engine to verify if the package exists for your arch.

**Q: The web search engine shows "Repository not available" or an empty state (∅).**
**A:** This usually means the GitHub Pages deployment is still processing a recent push, or the `packages.json` file is being generated by our CI/CD pipeline. Please wait a few minutes and refresh the page.

**Q: The web search engine shows a "Rate-limit" error (403).**
**A:** If the `packages.json` file is temporarily unavailable, the search engine falls back to the GitHub API, which has a strict limit of 60 requests per hour per IP. Please wait a few minutes or try again later.
